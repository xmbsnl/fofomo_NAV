# DT-01 算法手册

> 本手册说明 DT-01 导航系统现阶段使用的全部算法：从传感器预处理到建图、定位、
> 安全仲裁与巡线控制。所有参数均可在 `robot_ws/src/` 对应文件中调整。

---

## 1. 系统总览（数据流）

```
 飞迪 IMU 400Hz ──▶ imu_preprocess ──┐          蓝海雷达 ~15Hz ──▶ bluesea2 ──▶ /scan
 (降采样+零偏扣除)   /imu/data_fused │                              │
                                     ▼                              ▼
                          robot_localization EKF ◀──── odom_to_tf ──┘
                          (odom+IMU 融合, 50Hz)         │
                                     │                  │
                          /odom + TF(odom→base)         │
                                     │                  │
                    ┌────────────────┼──────────────────┤
                    ▼                ▼                   ▼
              slam_toolbox       AMCL(Nav2)        route_follower
               (建图模式)        (导航定位)        (打点连线巡线, 20Hz)
                    │                │                   │
                    ▼                ▼                   ▼
                 /map            map→odom TF          /cmd_vel_nav
                                     │                   │
                                     ▼                   ▼
                             ┌───────── safety_mux（安全仲裁）─────────┐
                             │  /cmd_vel_teleop（遥控，限速透传）        │

                                                ▼

```

## 2. 传感器预处理

### 2.1 IMU 预处理（`dt01_bringup/scripts/imu_preprocess.py`）

- **降采样**：飞迪 N100 原始 400Hz，直接灌 EKF 会导致 yaw 以约 1°/s 漂移、
  建图糊成扇形。这里降采样到 EKF 可消化的频率。
- **陀螺零偏扣除**：`gyro_bias_z` 参数（标定方法：机器人静止 20s，取
  `/imu/data` 的 wz 均值）。匀速漂移 = 零偏，随机游走 = 噪声，先分清再调。

### 2.2 EKF 融合（`dt01_bringup/config/ekf.yaml`）

robot_localization 扩展卡尔曼滤波，融合轮式里程计与 IMU：
- 轮式里程计提供 x/y/yaw 速度积分
- IMU（经预处理）提供角速度
- 输出统一 50Hz 的 `/odom` 与 `odom→base_link` TF

> 经验值：EKF 输出频率应为 50Hz；若测得 100Hz 说明起了两套系统（双 EKF
> 互发 TF，位姿跳变），先查进程再调参。

## 3. 建图：slam_toolbox

- 节点：`async_slam_toolbox_node`，参数 `dt01_bringup/config/mapper_params_real.yaml`
- 要点：
  - 建图车速 ≤0.3 m/s，**走闭合回路**（回环检测需要重访）
  - 地图分辨率 0.05 m/px
  - 保存：`/slam_toolbox/save_map` 服务或 nav2_map_server CLI

## 4. 定位：AMCL（自适应蒙特卡洛定位）

- 参数：`dt01_bringup/config/nav2_params_real.yaml` 的 `amcl` 段
- 初始位姿三来源（GUI 自动管理）：
  1. 每张地图保存的 `initial_pose.json`（出生点固定时长期复用）
  2. 手动点选（拖动设朝向）
  3. 全局定位（协方差拉满，粒子均匀重撒自动搜索，10~30s 收敛）

### 4.1 镜像退化问题（重要）

长走廊、成排对称工位等环境下，激光匹配存在旋转 180° 的等价解，
AMCL 可能收敛到镜像位姿——表现为**激光贴图左右反**。

- 检测：GUI 在设定初始位姿 4s 后核对 AMCL 输出，位置差 >0.6m 或
  航向差 >60° 即告警（见 `gui/dj_nav/main_window.py` 的
  `_verify_initial_pose`）
- 处置：重新设定初始位姿（车头朝向必须指对）或全局定位
- 预防：初始位姿尽量设在环境中**不对称**的位置（靠墙角、靠柱子）

### 4.2 初始位姿激光-地图精修（GUI 侧，`gui/dj_nav/pose_refiner.py`）

手动点选的初始位姿总有 ±0.3m / ±15° 级别的误差，对称环境下还可能落在
镜像解附近。GUI 在设定初始位姿 1.5s 后自动做一次相关扫描匹配精修：

1. 对地图占据栅格做 chamfer 3-4 距离变换（纯 numpy 向量化，O(h) 次运算）；
2. 把当前激光点变换到世界系，在 ±1.2m / ±50° 范围内按
   `0.12m/5° → 0.02m/0.8° → 0.005m/0.2°` 三级由粗到细搜索，
   平均距离场最小 = 激光与地图墙体贴合最好的刚体修正；
3. 修正量足够大（>5cm 或 >0.5°）时把修正位姿重发 `/initialpose`，
   并作为新的基准保存复用。

距离场在图外/远离障碍处封顶罚分，防止把激光"对"到地图空白/未知区域。
典型耗时 <1s，后台线程执行，不阻塞界面；机器人在动或无雷达数据时自动跳过。

## 5. 安全仲裁：safety_mux（`dt01_bringup/scripts/safety_mux.py`）

所有运动指令的**唯一出口**，优先级从高到低：

| 优先级 | 输入 | 说明 |
|---|---|---|
| 1 | 急停（遥控器 SWD） | 直接零速锁死 |
| 2 | 防撞（激光近距；DT-01D 机型另有超声参与） | 强制减速或停车 |
| 3 | 遥控 `/cmd_vel_teleop` | 限速透传 |
| 4 | 自主 `/cmd_vel_nav` | 限速透传 |

- 输出 `/cmd_vel` → dt_ros2 → 串口 → 底盘
- **规则**：任何自主/遥控代码严禁直接发布 `/cmd_vel`，必须走对应入口话题，
  否则绕过急停与防撞。
- 附带 `link_watchdog.py`：监控上位机链路，链路异常时保护性停车。

## 6. 巡线算法：route_follower（`gui/route_follower_node.py`）

核心思想：**不自由规划路径**。用户在地图上打点，相邻点连成最短直线段序列，
机器人是这条折线的"轨道车"。

### 6.1 路线表示与状态机

```
IDLE ──收到路线+start──▶ ROTATE(段1) ──对正──▶ DRIVE(段1) ──到点──▶ ROTATE(段2) ──▶ ... ──▶ DONE
  ▲                        │                      │
  └────── stop / 心跳超时 / 定位丢失 / 单点超时 ◀──┘
```

### 6.2 原地对正（ROTATE）

方位角比例控制，只发角速度、线速度为 0：

```
err = wrap(atan2(ty - ry, tx - rx) - yaw)
w  = clamp(kp_rot · err, ±w_max)
若 |w| < min_w: w = sign(w) · min_w     # 克服底盘静摩擦
收敛条件：|err| < 0.06 rad（约 3.4°）
```

### 6.3 直线跟踪（DRIVE）—— Pure Pursuit 前视点

把机器人位置投影回当前直线段，取投影点前方 `look_ahead` 处为目标点：

```
t      = ((p - S)·(T - S)) / |T - S|²        # 投影参数
t_look = min(1, t + look_ahead/|T-S|)         # 前视点参数（不越过目标）
aim    = S + t_look·(T - S) + n̂·avoid_off     # n̂ 为左法向，avoid_off 为避障偏移
err    = wrap(atan2(aim - p) - yaw)
w      = clamp(kp_lat · err, ±w_max)
```

前视点法保证横向误差收敛回线段（"严格走线"），且接近端点时平滑过渡到下一段。

### 6.4 避障（分层绕障，2026-09-29 重写）

激光取前方 ±25° 最近障碍距离 `front`，按距离分四层，核心是**永远边转边走**，
不在障碍前停车干转（静态障碍原地转永远绕不开）：

```
front > avoid_far (1.5m)   安全区：纯巡线全速，横向偏移慢回
1.0 ~ 1.5m                 预警区：小角度(0.27→0.52 rad/s)提前变道，几乎不减速
0.22 ~ 1.0m (avoid_near)   近距区：满转向(avoid_w) + 保持前进(v_turn_min)
≤ 0.22m (stop_dist)        紧急区：满转向 + 蠕行(v_creep)
```

配套机制：
- **绕行侧记忆**：进入避障时锁定一侧（左/右），障碍彻底离开才释放，
  防止在障碍正中左右摇摆；
- **回线弱化**：`recover_rate`=0.98 指数慢回，绕完由巡线自然导回，不急拉；
- `v_creep` 设 0 退化为"停车等待"（有人挡路的保守场景）；
- 关键性质不变：避障不需要重规划，偏移是叠加在前视点上的临时横移，
  障碍解除即恢复原路线。各参数释义见 docs/调参手册.md 第四节。

### 6.5 电子围栏（Keepout，巡线层实现）

- GUI 在地图上画禁区多边形（≥3 点闭合），按地图持久化到
  `gui/config/keepout_zones.json`，通过 `/dt01/route/keepout` 下发（JSON），
  并随路线包周期重发（节点侧幂等）；
- 节点收到后两处拦截：
  1. **路线点过滤**：目标点落在任一禁区内（射线法）→ 剔除并告警，
     全部点都在禁区 → 整条路线拒绝执行；
  2. **巡线实时校验**：当前段目标点进入禁区 → 立即停车；
- GUI 侧打点时同样做禁区拦截，双保险。

### 6.6 断链看门狗（真车安全核心）

- GUI 以 2Hz 发 `/dt01/route/heartbeat`
- 节点超过 `hb_timeout`(2s) 收不到 → 零速停车（覆盖 WiFi 断开、GUI 崩溃）
- 节点输出固定走 `/cmd_vel_nav` → safety_mux（急停/防撞全生效）

### 6.7 其余保护

| 保护 | 行为 |
|---|---|
| 定位丢失（/amcl_pose 断流） | 停车等待恢复 |
| 单点超时 90s | 跳过该点继续下一段 |
| 到点判定 | 距目标 < `arrive_tol`(0.15m) 停车进入下一段 |
